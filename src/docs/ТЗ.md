## 2. НЕДЕЛЯ 1: РЕАЛЬНЫЙ VPN + WEBSOCKET ЧАТ

### 2.1 WebSocket Chat Hub (MUST)

**Цель:** Два человека открывают URL → пишут сообщения → видят в реальном времени

**Задачи:**
1. Добавить WebSocket endpoint `/ws` в Go webserver
2. Реализовать Chat Hub: регистрация клиентов, broadcast, direct messages
3. Каждый клиент = userId (пока = random, потом = npub)
4. Формат сообщений: `{"type":"chat","from":"userId","text":"...","ts":123456}`
5. Frontend: подключение WS, отправка/получение, онлайн-индикатор
6. Reconnect при обрыве (exponential backoff)
7. Индикация «печатает...» (typing indicator)

**Файлы:**
- `src-vpn/cmd/webserver/ws.go` — WebSocket hub
- `src-vpn/cmd/webserver/main.go` — добавить `/ws` route
- `dist/index.html` — обновить JS для WebSocket

**Технологии:**
- Go: `nhooyr.io/websocket` или `github.com/gorilla/websocket`
- JS: нативный `new WebSocket(url)`

**Время:** 8 часов

### 2.2 VPN Manager → Real Integration (MUST)

**Цель:** Кнопка «Поделись интернетом» реально создаёт WireGuard интерфейс

**Задачи:**
1. Подключить `src-vpn/vpn.go` к webserver (убрать stub)
2. Реальная генерация ключей: `golang.org/x/crypto/curve25519` (без `wg` CLI)
3. Создание WG интерфейса: `ip link add`, `wg set`, IP назначение
4. Exit node: NAT через iptables, forwarding
5. Сохранение конфигурации в `~/.unkillable-messenger/vpn/`
6. Статус: реально опрашивать `wg show` или ioctl
7. Обработка ошибок: нет прав → подсказка `sudo`, нет WG → инструкция установки

**Файлы:**
- `src-vpn/vpn.go` — дописать реальные вызовы
- `src-vpn/cmd/webserver/vpn_handlers.go` — API handlers для VPN
- `src-vpn/cmd/webserver/main.go` — подключить

**Время:** 12 часов

### 2.3 Peer Management (MUST)

**Цель:** Добавить друга по публичному ключу → он появляется в списке

**Задачи:**
1. API: `POST /api/peers` (name, publicKey, endpoint)
2. API: `GET /api/peers` — список с online/offline
3. API: `DELETE /api/peers/:id`
4. Сохранение peers в JSON файл (потом → SQLite)
5. Heartbeat: каждый peer пингуется раз в 30 сек
6. Frontend: форма «Добавить друга» + список peers

**Время:** 6 часов

### 2.4 Identity v1 (MUST)

**Цель:** При первом запуске генерируется ключевая пара, userId = npub

**Задачи:**
1. Go: генерация secp256k1 ключевой пары (btcd/btcutil)
2. Go: формат npub/nsec (bech32 кодирование)
3. Go: сохранение в `~/.unkillable-messenger/identity.json`
4. API: `GET /api/identity` — публичный ключ, npub
5. Frontend: показать «Твой ID: npub1...» с кнопкой копирования
6. Seed phrase: BIP39 мнемоника из ключа (для восстановления)

**Время:** 6 часов

**ИТОГО НЕДЕЛЯ 1:** ~32 часа

## 3. НЕДЕЛЯ 2: NOSTR-ПРОТОКОЛ + ШИФРОВАНИЕ

### 3.1 Nostr Client (Go) (MUST)

**Цель:** Приложение подключается к Nostr relay, подписывается на события

**Задачи:**
1. WebSocket клиент к relay (wss://relay.damus.io, wss://nos.lol, и т.д.)
2. NIP-01: отправка событий, подписка на фильтры
3. NIP-04/NIP-44: E2E шифрование DM
4. Reconnect при обрыве relay
5. Пул relay'ев (3-5 одновременно для redundancy)
6. События kind:0 (metadata), kind:1 (note), kind:4 (DM), kind:40-42 (channels)

**Файлы:**
- `src-vpn/nostr/client.go` — WebSocket клиент
- `src-vpn/nostr/event.go` — создание/верификация событий
- `src-vpn/nostr/filter.go` — подписки
- `src-vpn/nostr/relay.go` — relay pool management
- `src-vpn/nostr/encrypt.go` — NIP-44 шифрование

**Время:** 12 часов

### 3.2 Nostr ↔ Chat Bridge (MUST)

**Цель:** Сообщения из чата = NIP-04 DM через Nostr

**Задачи:**
1. Chat Hub перенаправляет сообщения через Nostr client
2. Входящие Nostr DM → отображаются в чате
3. Групповые чаты через NIP-28 (channel messages)
4. Поддержка offline: relay хранит события, при подключении подгружаются

**Время:** 8 часов

### 3.3 Свой Nostr Relay (MUST)

**Цель:** Embedded relay для backup (когда внешние relay недоступны)

**Задачи:**
1. Простой WebSocket relay на Go
2. Хранение событий в SQLite
3. NIP-01 совместимый (подписки, фильтры)
4. Запускается на порту 4040 (или рядом с webserver)
5. Автоматически добавляется в relay pool

**Файлы:**
- `src-vpn/nostr/relay_embedded.go`

**Время:** 8 часов

### 3.4 Шифрование файлов (NICE → MUST в Phase 2)

Пока откладываем. Файлы передаются через VPN tunnel (шифрование на уровне WireGuard).

**Время:** 0 часов (перенос на неделю 3-4)

### 3.5 Профиль пользователя (NICE)

**Задачи:**
1. NIP-01 kind:0 — metadata event (name, about, picture URL)
2. UI: редактирование профиля
3. Загрузка аватара (пока: URL или base64 в event)

**Время:** 4 часа

**ИТОГО НЕДЕЛЯ 2:** ~32 часа

## 4. НЕДЕЛЯ 3: КАНАЛЫ + ФАЙЛОВЫЙ ОБМЕН

### 4.1 Каналы (Nostr NIP-28) (MUST)

**Цель:** Создание канала, подписка, публикация постов

**Задачи:**
1. kind:40 — создание канала (name, about, picture)
2. kind:41 — обновление metadata канала
3. kind:42 — сообщение в канале
4. API: `GET /api/channels`, `POST /api/channels`, `POST /api/channels/:id/posts`
5. Frontend: список каналов, создание, посты, подписка
6. Кросс-постинг: Telegram bot bridge (NICE)

**Время:** 10 часов

### 4.2 Файловый обмен через VPN (MUST)

**Цель:** Drag-and-drop файл → передаётся через WireGuard tunnel

**Задачи:**
1. API: `POST /api/files/upload` (multipart, до 100MB)
2. API: `GET /api/files/:id` — скачивание
3. Хранение в `~/.unkillable-messenger/files/`
4. Frontend: drag-and-drop зона в чате
5. Прогресс-бар загрузки/скачивания
6. Привязка файла к сообщению (message.fileId)

**Время:** 8 часов

### 4.3 IPFS Gateway (NICE)

**Цель:** Файлы хранятся в IPFS для неубиваемости

**Задачи:**
1. Опциональный embedded IPFS node (go-ipfs или lite)
2. Upload → pin → получить CID
3. Скачивание по CID из IPFS network
4. Fallback: если IPFS недоступен, файлы на relay

**Время:** 6 часов (NICE, можно в Phase 2)

### 4.4 Push-уведомления (NICE)

1. Web Push API (VAPID ключи)
2. Go: подписка на push, отправка уведомлений
3. Frontend: запрос разрешения, обработка push

**Время:** 4 часа

**ИТОГО НЕДЕЛЯ 3:** ~28 часов

## 9. КРИТЕРИИ ГОТОВНОСТИ MVP

### MVP готов когда:

- [ ] Два человека могут обменяться сообщениями в реальном времени
- [ ] Кнопка «Поделись интернетом» реально создаёт WireGuard exit node
- [ ] Сообщения зашифрованы (NIP-04 минимум)
- [ ] Есть identity = npub, seed phrase для восстановления
- [ ] Можно создать канал и опубликовать пост
- [ ] Можно передать файл через VPN tunnel
- [ ] Работает из-за NAT (Cloudflare tunnel или STUN)
- [ ] PWA устанавливается на телефон
- [ ] Tauri desktop собирается для Linux

### MVP НЕ включает (Phase 2):
- IPFS (файлы хранятся локально + на relay)
- Tor transport
- WebRTC звонки
- Групповые чаты (NIP-28 shared key)
- Telegram cross-posting
- Мобильные приложения (только PWA)
- Premium подписка
- iOS/Android native
